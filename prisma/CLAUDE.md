# prisma — Database rules

## Schema & migrations

- The app uses **PostgreSQL** with **Prisma ORM**. Models live in `prisma/schema.prisma`; migrations in `prisma/migrations/`.
- Update `schema.prisma` and create a migration **together** — run `npx prisma migrate dev` after any schema change.
- Run `npx prisma generate` if generated client types change (it also runs via `postinstall`).
- Update `prisma/seed.ts` if a schema change affects seed data.
- Use `npx prisma studio` to inspect the database.

## Main models

- **User** — accounts with `authorized` whitelist flag.
- **PlaidAccount** — connected bank accounts via Plaid.
- **Transaction** — individual financial transactions.
- **Report** / **RecurringReport** — monthly/annual and recurring categorized spending.
- **RecurringTransaction** — recurring income/expenses.
- **Note** — user notes/annotations.

## Generated client — do not edit

- The generated Prisma client lives at `src/generated/prisma` and is **git-ignored** (regenerated by `prisma generate` in `postinstall`/build). Never edit it by hand; ESLint already ignores it.

## Conventions

- **Staging column naming:** staging columns are `<entityName>Uuid` (e.g. `reportUuid`, `plaidAccountUuid`); a bare `id` maps to `uuid`.
- RLS posture for the `public` schema is security-critical — see `src/app/api/mobile/CLAUDE.md` before changing roles, policies, or adding new public tables.
